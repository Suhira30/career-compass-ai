# Career Compass AI — Technical & Soft Skill Taxonomy

This document defines the technical, engineering, AI, data, professional, and interview skill taxonomy used by **Career Compass AI** for:

- Resume skill extraction
- Job description skill extraction
- Skill-gap analysis
- Career recommendations
- Interview preparation
- Learning recommendations
- Personalized upskilling roadmaps

The taxonomy is designed around the following hierarchy:

**Career Domain → Skill Category → Skill → Technology / Tool / Concept**

# 20. Skill Metadata Model

Each skill should ideally contain structured metadata in addition to its textual description.

Recommended metadata:

- `skill_id`
- `name`
- `domain`
- `category`
- `skill_type`
- `description`
- `parent_skills`
- `related_skills`
- `prerequisites`
- `technologies`
- `difficulty`
- `interview_relevance`
- `production_relevance`
- `learning_outcomes`

Example:

```json
{
  "skill_id": "backend.spring_boot",
  "name": "Spring Boot",
  "domain": "Software Engineering",
  "category": "Backend Development",
  "skill_type": "framework",
  "description": "Java framework for building production-ready backend applications.",
  "parent_skills": ["backend.java", "api.rest"],
  "related_skills": ["spring-security", "spring-data", "dependency-injection"],
  "prerequisites": ["java", "oop", "http", "sql"],
  "difficulty": "intermediate",
  "interview_relevance": "high",
  "production_relevance": "high"
}
```

# 22. Important Design Principle

Career Compass AI should not operate as a simple **technology matching system**.

It should operate as a **competency matching system**.

For example, instead of only detecting:

```text
Java
Spring Boot
PostgreSQL
Docker
```

the system should understand the broader competency:

```text
Backend Engineering

├── Programming
│   └── Java
│
├── Framework
│   └── Spring Boot
│
├── API Engineering
│   └── REST
│
├── Database Engineering
│   └── PostgreSQL
│
├── Testing
│   └── Unit / Integration Testing
│
├── Security
│   └── Authentication / Authorization
│
├── Distributed Systems
│   └── Messaging / Caching
│
├── DevOps
│   └── Docker
│
└── Observability
    └── Logging / Metrics / Tracing
```

This competency-based approach enables Career Compass AI to provide more meaningful:

- Skill-gap analysis
- Career recommendations
- Interview preparation
- Learning paths
- Upskilling recommendations
- Job matching
- Personalized development plans

# 23. Recommended RAG Representation

For RAG implementation, the taxonomy should ideally be stored as **individual skill documents** rather than only one large document.

For example:

```text
knowledge_base/
├── software_engineering/
│   ├── java.md
│   ├── spring_boot.md
│   ├── oop.md
│   ├── data_structures.md
│   ├── algorithms.md
│   ├── testing.md
│   └── system_design.md
│
├── databases/
│   ├── postgresql.md
│   ├── mysql.md
│   ├── mongodb.md
│   └── redis.md
│
├── devops/
│   ├── docker.md
│   ├── kubernetes.md
│   ├── ci_cd.md
│   └── terraform.md
│
├── ai/
│   ├── machine_learning.md
│   ├── llm.md
│   ├── embeddings.md
│   ├── rag.md
│   ├── vector_databases.md
│   └── ai_agents.md
│
└── professional/
    ├── communication.md
    ├── teamwork.md
    ├── problem_solving.md
    └── leadership.md
```

Each document can contain:

1. Skill name
2. Definition
3. Category
4. Prerequisites
5. Related skills
6. Technologies
7. Difficulty
8. Interview relevance
9. Production relevance
10. Learning outcomes
11. Common job-description terminology
12. Interview topics

This structure will make the Career Compass RAG system substantially more useful than embedding one large taxonomy document.
